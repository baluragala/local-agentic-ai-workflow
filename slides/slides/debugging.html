06 · COMMON FAILURE POINTS

Find the first wrong event

Failure pointSymptomMitigation
Interpretationwrong intent, invented order IDstructured output + “must appear in text” guard
Tool selectionunknown or skipped toolvalidator, clearer descriptions, preconditions
Argumentswrong names, types, amountsschema check, coercion, cross-check results
Output formattool call written as textrecovery parser in the LLM wrapper
Fake successfluent answer, no ticketcompletion check; status from tool results
Loopingsame call repeatedmax_steps safety stop

Reproduce → read the trace by layer → find the first wrong event → script the model → fix → add a test case.

This is the debugging workflow learners should take away. diagnose(state) automates the first pass: it lists rejected calls, tool errors, incomplete runs and IDs or amounts in the answer that no tool produced.
