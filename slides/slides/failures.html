04 · FAILURES ON PURPOSE

Scripted failures, on purpose

buggy_model = ScriptedLLM([
 PLAN_JSON,
 issue_refund(...)        # invented tool
 get_order(order=1002)   # wrong arg
 get_order(order_id=...)
 calculate_refund(...)   # skipped step
 check_return_eligibility(...),
 calculate_refund(...),
 create_ticket(amount=1490) # wrong $
 create_ticket(amount="149.00"),
 "Your return RET-1002 ..."])
Bad requestCaught by
Unknown tool🛡️ name check
Wrong argument name🛡️ schema check
Refund before eligibility🛡️ precondition
Amount 1490 ≠ 149🛡️ cross-check
"149.00" as stringcoerced, accepted
Order ORD-9999🔧 tool error → honest reply

The orchestrator cannot tell a scripted model from a real one, which proves the control logic lives in the application.

Every bad request is rejected and never executed; the error goes back so the model can self-correct, and the run still ends in ticket_created. Scripting the model is a standard debugging technique: make the failure deterministic, then fix it.
